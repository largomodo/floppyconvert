# header/

512-byte copier-header generators (per format) plus SRAM-encoder strategies.

## Files

| File                            | What                                                                                                                                                                                                                                                                              | When to read                                                                                                                                |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `README.md`                     | Format-specific quirks (FIG headers on all parts, GD3 first-part-only, 8 Mbit alignment), SRAM-encoder strategy pattern, SRAM encoding tables, memory-map selection logic, DSP flag handling, `partSize`/`chunkFlag` parameter usage, idempotence warning for SRAM encoders        | Understanding copier format differences, debugging header generation, adding new format support, understanding per-part vs total ROM size  |
| `HeaderGenerator.java`          | Interface: `generateHeader(SnesRom, partSize, splitPartIndex, isLastPart, chunkFlag)` → `byte[512]` (or empty); `partSize` per-part size for block calc; `chunkFlag` enables UFO irregular chunk flag (0x40/0x10/0x00); non-UFO formats ignore `chunkFlag`                          | Adding new copier formats, understanding the generation contract, understanding `partSize`/`chunkFlag` usage                                |
| `HeaderGeneratorFactory.java`   | Returns SWC/FIG/UFO/GD3 generator based on `CopierFormat`; injects format-specific `SramEncoder`                                                                                                                                                                                  | Adding new format support, debugging generator selection                                                                                    |
| `SramEncoder.java`              | Strategy interface: `encodeSram(byte[], SnesRom)` mutates header at format-specific byte offsets                                                                                                                                                                                  | Understanding SRAM encoding abstraction, adding new encoding strategies                                                                     |
| `SwcSramEncoder.java`           | SWC: byte 2 (`0x0C` / `0x08` / `0x04` / `0x00` for 256KB / 64KB / 16KB / 0KB)                                                                                                                                                                                                      | Debugging SWC SRAM encoding                                                                                                                 |
| `FigSramEncoder.java`           | FIG: byte 3 (same code mapping as SWC)                                                                                                                                                                                                                                            | Debugging FIG SRAM encoding                                                                                                                 |
| `UfoSramEncoder.java`           | UFO: byte 4 size codes (0/1/2/3/8 for 0KB/16KB/64KB/256KB/512KB), bytes 5-6 mapping controls (A15, A20-A23)                                                                                                                                                                       | Debugging UFO SRAM encoding, understanding mapping controls                                                                                 |
| `Gd3SramEncoder.java`           | GD3 HiROM byte 7 (`0x29` with SRAM, `0x2A` without); LoROM byte 2 (`0x14` DSP+SRAM, `0x1C` DSP-only, `0x24` SRAM-only, `0x28` neither)                                                                                                                                            | Debugging GD3 SRAM encoding, understanding HiROM vs LoROM differences                                                                       |
| `SwcHeaderGenerator.java`       | SWC: emulation `0x30` HiROM / `0x00` LoROM, multi-file flag `0x40`, fixed IDs `0xAA`/`0xBB`/`0x04`, size in 8KB blocks from `partSize`; ignores `chunkFlag`                                                                                                                          | Debugging SWC headers, understanding emulation flags, `partSize` usage                                                                      |
| `FigHeaderGenerator.java`       | FIG: HiROM flag `0x80`, multi-file flag `0x40`, emulation bytes with DSP logic, headers on **all** parts, size in 8KB blocks from `partSize`; ignores `chunkFlag`                                                                                                                  | Debugging FIG headers, DSP flag encoding, multi-part behavior                                                                               |
| `UfoHeaderGenerator.java`       | UFO: `"SUPERUFO"` ID, bank type (0 HiROM / 1 LoROM), dual-source size (`partSize` for bytes 0-1, total ROM size for byte 17), uses `chunkFlag` for byte 2                                                                                                                          | Debugging UFO headers, understanding dual-source size encoding, `chunkFlag` usage                                                           |
| `Gd3HeaderGenerator.java`       | GD3: `"GAME DOCTOR SF 3"` ID, **first-part-only** headers (empty `byte[]` for parts > 0), memory-map tables (8/16/24/32 MB HiROM, 4/8/16/32 MB LoROM) selected from total ROM size; ignores `partSize` and `chunkFlag`                                                              | Debugging GD3 headers, memory-map tables, why `partSize` is ignored                                                                         |
